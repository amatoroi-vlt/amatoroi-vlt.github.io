1. 개요

목표. 코스피·코스닥 보통주를 대상으로, 종목별 33거래일의 가격/거래량 패턴만으로 "34일째 종가에 매수해 35일째 시가에 매도"했을 때의 수익률을 예측하고, 매일 상위 5종목을 골라 실제로 운용 가능한 신호를 만든다.

과정. 동일한 데이터 파이프라인과 Conv1D+BiGRU 회귀 모델을 뼈대로, 5차례에 걸쳐 타깃 정의(시장중립화), 입력 피처(당일 갭/거래량 aux), 손실함수(회귀 → 랭킹 → top-k 가중 랭킹 → 회귀+랭킹 혼합) 세 축을 순차적으로 개선했다.

결론(요약). v1 대비 v2~v5 전부 큰 폭으로 개선(일평균수익률 기준 전체 후보 평균 대비 5~9배 알파). 절대 수익률은 v2가 가장 높고, 승률·위험조정수익(Sharpe 유사치)은 v4·v5가 근소하게 앞선다 — 다섯 버전이 "확연한 우열"이라기보다 비슷한 성능대 안에서의 트레이드오프에 가깝다. 자세한 수치와 해석은 5장·6장 참고.

2. 문제 정의

단기 트레이딩 신호를 만들 때 가장 다루기 쉬운 구조는 "오버나잇 갭"이다 — 장중 변동성을 안고 가지 않고, 전날 종가와 다음날 시가 사이의 갭만 포착한다. 그래서 태스크를 다음과 같이 고정했다:

  • 입력: 종목별 33거래일치 [전일 종가 대비 로그수익률(시/고/저/종) + 거래량 z-score] — 5개 피처
  • 라벨: (35일째 시가 − 34일째 종가) / 34일째 종가 × 100 (%)
  • 중요 제약: 윈도우는 34·35일째 데이터를 전혀 보지 않는다 — lookahead 누수 없음

이 구조가 왜 타당한지는 v1 실험(§4.1)에서 "시가 매수 vs 종가 매수" 두 방식을 직접 비교해 실증적으로 확인했다.

3. 데이터 및 방법론

3.1 데이터 파이프라인

원본: data/market.duckdb의 candles(종목별 OHLCV, 2005~2026), universe(종목 마스터). 스팩(SPAC) 73종목과 최소 거래일수(300일) 미만 종목은 제외.

이상치 제거: 거래정지(거래량 0), ±32% 초과 급등락(액면분할·데이터 오류 추정)이 낀 윈도우는 학습·평가 모두에서 제외.

전체 규모: 종목별로 하루씩 밀며 생성(stride=1, 겹침 허용) 시 전체 6,230,402개 윈도우 → 분할·embargo 이후 학습 가능 윈도우 약 559만개.

3.2 데이터 유니버스 보정 — 우선주 제외

뒤늦게 발견된 문제. 라이브 픽 운용을 시작한 뒤에야, 학습 유니버스에 우선주(예: 삼성전자우)가 걸러지지 않은 채 섞여 있었다는 게 드러났다 — 실제로 어느 날 5개 픽 중 2개가 우선주였다. 우선주는 발행주식수가 적고 유동성·가격 움직임이 보통주와 다른 경우가 많아, 모델이 "우선주 특유의 패턴"을 보통주와 뒤섞어 학습했을 가능성이 있다.

수정: 이름 패턴(예: "우"로 끝나는 종목)을 걸러내는 블랙리스트 방식은 에코글로우·성우처럼 이름이 "우"로 끝나지만 실제로는 보통주인 종목에서 오탐이 확인되어 채택하지 않았다. 대신 KRX 공식 종목기본정보의 KIND_STKCERT_TP_NM 필드(보통주/구형우선주/신형우선주/종류주권)를 기준으로 보통주만 화이트리스트로 남기는 방식을 채택 — 알려지지 않은 미래의 새 분류값이 나와도 안전하게 배제되는 구조다. 결과: KOSPI+KOSDAQ 총 2,766종목 중 2,653종목(보통주)만 화이트리스트, 113종목(우선주·종류주권) 제외.

이 필터를 data_prep.py·라이브 픽 스크립트 양쪽에 반영한 뒤, v1~v5 전부 데이터 재생성 + 재학습했다. 이 문서 5장의 모든 수치는 이 재학습 결과 기준이다.

3.3 Train / Val / Test 분할 — 블록-랜덤 + Embargo

단순 시간순 분할(예: ~2022 train, 2023 val, 2024~ test)은 특정 구간에 강세장/약세장이 편중될 위험이 있어 채택하지 않았다. 대신:

  1. 전체 기간(2005~2026)을 6개월 단위 블록 44개로 분할
  2. 블록을 무작위로 train(70%) / val(15%) / test(15%)에 배정(seed=42)
  3. 겹치는 윈도우(같은 33일 중 32일 공유)가 서로 다른 split에 걸치지 않도록, 블록 경계를 넘나드는 윈도우는 embargo로 전량 제외(약 10%)
  4. 각 split 내 저장 순서를 한 번 무작위로 섞어 디스크에 저장 → 학습 시 순차읽기만으로 충분히 랜덤 (mmap I/O 병목 해소)

세 split 모두 20년 전체에 걸쳐 흩어져 있어 특정 장세에 편중되지 않는다. Test set은 593,539개 윈도우, 575거래일 — 모든 버전이 동일한 분할을 공유해 공정 비교가 가능하다.

3.4 모델 아키텍처

GapReturnNet: Conv1d(5→32, k=3) × 2  +  BiGRU(hidden=64)  +  Linear head
파라미터 ≈ 50,000개
optimizer: AdamW(lr=1e-3) · batch_size=1024 · epochs=15 · device=MPS

v2부터는 33일 시퀀스를 인코딩하는 GRU 브랜치에, 당일(34일째) aux 피처를 처리하는 작은 MLP 브랜치를 병렬로 추가하고 concat 후 head를 통과시키는 2-branch 구조로 확장했다.

3.5 평가지표

  • MAE / Pearson / Spearman: 예측값과 실제 수익률의 표준 회귀·순위 상관 지표
  • Top-decile spread: 그날 후보군 안에서 예측 상위 10% − 하위 10%의 실제 평균수익률 차이. 반드시 날짜별로 계산한 뒤 평균(day-grouped) — 전체를 날짜 구분 없이 섞어 계산하면 "시장 전체가 오른 날"에 편향되어, 순수한 종목 간 순위 변별력이 아니라 시장 방향성만 측정하게 되는 문제를 v1→v2 사이에 발견하고 고쳤다.
  • Sharpe-like: 연율화하지 않은 (평균수익률 / 표준편차) — 일 단위(그날 5종목 평균)와 거래 단위(종목 개별) 두 가지로 각각 계산

4. 실험 계보: v1 → v5

v1_baseline      : 5-feature 윈도우, 회귀(raw target), 블록-랜덤 분할
v2_demeaned_aux  : + 타깃 시장중립화(day-demean) + day-34 갭/거래량 aux 피처
v3_ranking_loss  : 회귀 → RankNet pairwise ranking loss (무작위 쌍)로 교체
v4_ranking_topk  : pairwise 쌍 샘플링을 top-k(예측 상위 20개) 가중으로 개선 (LambdaRank 스타일)
v5_combined      : 회귀(v2 방식) + 랭킹(v4 방식)을 가중합으로 동시 학습

4.1 v1 — Baseline 기준선

회귀(SmoothL1)로 raw 수익률을 직접 예측하는 가장 단순한 형태. 이 실험에서 두 가지를 검증했다:

  • 진입 타이밍: "34일째 시가 매수 → 35일째 시가 매도"(평균수익 0.20%, 승률 46.3%) vs 채택한 "34일째 종가 매수 → 35일째 시가 매도"(평균수익 0.78%, 승률 55.8%). 모델이 34일째 장중 정보를 전혀 보지 못하므로, 시가에 사서 장중 변동성까지 떠안는 방식은 예측 불가능한 노이즈만 추가해 성과가 급락함을 확인.
  • 사후 필터 탐색: 갭업 3% 이상, 거래량 3배 이상인 종목만 추리면 성과가 단조적으로 개선(Sharpe 0.235→0.384). 이건 "모델이 이미 보고 있는 정보"가 아니라 사후 필터라, 다음 버전에서 이 신호를 모델 입력에 직접 반영하기로 함.

4.2 v2 — 타깃 시장중립화 + day-34 aux 피처

변경 1 — 타깃 시장중립화: 학습 타깃을 raw 수익률 대신, 그날(buy_date) 횡단면 평균을 뺀 y_demeaned로 바꿈. 모델이 "시장 전체가 오르는 날" 같은 공통 변동이 아니라 종목 고유 패턴에 집중하도록 유도.

변경 2 — aux 피처 추가: v1에서 사후 필터로만 검증됐던 두 신호 — 개장 갭 log(open_34/close_33), 거래량 서지 log(volume_34/윈도우평균volume) — 를 모델이 직접 학습하는 별도 side-input으로 추가 (GRU 시퀀스 임베딩 + aux MLP → concat → head).

두 변경을 동시에 적용해, 어느 쪽 기여가 더 큰지는 이 실험만으로는 분리되지 않는다(ablation 미실시, §7 한계 참고).

4.3 v3 — RankNet pairwise ranking loss

손실함수를 회귀에서 랭킹으로 교체 — 같은 날짜 후보 안에서 무작위로 종목 쌍을 뽑아 "실제 수익률이 더 높은 쪽이 예측값도 더 높아야 한다"만 학습. 실제로 매일 상위 K개를 뽑아 쓰는 우리 사용 방식과 목적함수를 직접 일치시킨다는 이론적 장점이 있었다. 이를 위해 같은 날짜끼리만 배치를 구성하는 DayGroupedSampler와, "날짜별로 묶되 블록 순서만 섞는" 디스크 저장 방식을 새로 구현.

흥미로운 결과: top-decile spread(넓은 범위의 순위 품질)는 v2보다 개선됐지만, 정작 실전에서 쓰는 "상위 5종목 뽑기" 성과는 v2보다 낮았다. 원인으로 추정한 것: 쌍을 완전 무작위로 뽑다 보니 대부분 "중간 순위끼리의 비교"만 학습되고, 정작 필요한 "1등이 2~5등보다 확실히 위"라는 극단값 비교는 상대적으로 덜 학습됨.

4.4 v4 — top-k 가중 랭킹 손실 (LambdaRank 스타일)

v3의 문제(무작위 쌍 샘플링이 극상위 정밀도를 놓침)를 풀기 위해, 쌍의 절반(top_frac=0.5)은 무작위가 아니라 모델이 그 순간 예측한 상위 20개(top_m=20, detach) 중 하나를 반드시 포함하도록 뽑고, 나머지 절반은 기존처럼 무작위로 유지. "1등 후보가 나머지보다 정말 위에 있는가"를 집중 학습시키면서도 전체 순위 감각은 잃지 않게 균형을 맞춘 설계.

실제 학습 전에 합성 데이터로 30회 시행 검증: 무작위 쌍 방식은 실제 top-5 중 평균 0.57개만 맞췄는데, top-k 가중 방식은 0.90개를 맞혀 — 개선 방향이 맞다는 걸 먼저 확인한 뒤 실제 학습을 진행했다.

4.5 v5 — 회귀 + 랭킹 혼합 손실 현재 권장

v4까지도 남아있던 문제: 랭킹 계열(v3, v4)은 순서는 잘 맞추는데, 회귀 기반 v2에 비해 실제 수익률 "크기" 신호가 약해 평균수익률이 v2보다 낮았다. 이를 풀기 위해 같은 배치에서 회귀와 랭킹을 동시에 학습:

loss = SmoothL1(pred, y_demeaned_정규화)
     + combo_ranking_weight(=1.0) × topk_weighted_ranking_loss(pred, y)

회귀항이 "수익률 크기"를, 랭킹항이 "그날 순서"를 각각 담당하도록 역할을 분담시킨 설계다.

5개 연도 모두에서 v1 대비 전부 개선 — 특정 장세에 과적합된 결과가 아니라 20년에 걸쳐 일관된 향상이다. 2020년(COVID 변동성 장세)에서 개선폭이 가장 크게 나타나는 공통 패턴도 눈에 띈다.

6. 논의: 트레이드오프와 해석

다섯 버전이 확연히 갈리기보다는, 비슷한 성능대 안에서 서로 다른 축을 최적화한 결과에 가깝다.
  • 절대 수익률 극대화가 목표라면 → v2(일평균 1.35%, 최고) — 수익 규모가 큰 소수 거래에서 크게 이기는 경향
  • 승률·안정성이 목표라면 → v4(일 승률 82.6%, 최고)
  • 위험 대비 수익(Sharpe)이 목표라면 → v5(일/거래 Sharpe 모두 최고)
반복 매매로 자본을 복리 성장시키는 이 프로젝트의 성격을 고려하면, 절대수익 하나만 보기보다는 Sharpe·승률이 고르게 좋은 v4 또는 v5가 실전에는 더 유리할 가능성이 높다. 라이브 파이프라인에서 v2/v4/v5 셋 다 동시에 운용하며 실제 트랙레코드로 최종 판단하기로 한 것(§8)은 이 트레이드오프가 이론만으로는 완전히 해소되지 않는다는 뜻이기도 하다.

재학습 이후 순위가 미묘하게 바뀐 점도 주목할 만하다 — 이전(우선주 포함) 학습에서는 v5가 승률·Sharpe 모두 최고였지만, 보통주만으로 재학습하니 v4가 일 승률에서 v5를 앞섰다(82.6% vs 79.5%). 유니버스를 바꾸는 것만으로도 "어느 손실함수가 이기는가"의 순위가 흔들릴 수 있다는 뜻으로, 이 비교 자체가 시드·유니버스에 다소 민감할 수 있음을 시사한다(§7).

7. 한계 및 열린 문제

  1. 단일 시드 — 5개 버전 모두 시드 1개로만 학습됨. 버전 간 차이가 손실함수의 진짜 효과인지, 시드에 따른 우연인지 완전히 분리되지 않음.
  2. v2의 ablation 미실시 — 타깃 시장중립화와 aux 피처를 동시에 넣어, 두 변경 중 어느 쪽이 더 크게 기여했는지 분리되지 않음.
  3. 거래비용/슬리피지 미반영 — 모든 백테스트 수치는 순수 가격 기준이며 수수료·세금·슬리피지가 빠져 있음.
  4. 복리 누적수익률 미계산 — test 거래일이 블록-랜덤 특성상 20년에 걸쳐 비연속적으로 분포해, 공백 기간에도 자본이 투자된 것처럼 오해할 수 있는 복리 누적수익률은 의도적으로 계산하지 않음.
  5. 유동성 필터 부재(학습 단계) — 초소형주가 상위 5에 자주 등장함. 라이브 파이프라인에서는 호가창 체결 가능성만 확인할 뿐(§8), "적정 매매 규모"까지 보장하지는 않음.
  6. 문서-실체 불일치 — 이 문서 작성 중 발견: 우선주 필터 재학습(§3.2) 이후 각 버전의 REPORT.md 본문 수치가 갱신되지 않아, 아카이브된 최신 체크포인트/CSV와 어긋나 있었음(이 문서 5장은 최신 아티팩트에서 직접 재계산해 바로잡음). REPORT.md 본문도 재생성이 필요함.

8. 현재 실전 적용 현황

v2/v4/v5 세 모델을 매일 동시에 운용 중이다 — 장마감 직전(15:19)에 그날의 실제 갭·거래량으로 각 모델의 상위 5종목을 뽑고, 토스증권 호가창으로 체결 가능성을 확인한 뒤 확정한다. 다음날 아침 매도가가 확정되면 실현수익률을 계산해 runs/live_report.html에 모델별 트랙레코드(승률/평균·누적수익률/MDD)로 누적한다. 2026-07-15에 시작한 초기 단계로, 아직 실현된 거래가 쌓이지 않았고 실제 주문 제출은 자동화되지 않은 수동 단계다. 이 트랙레코드가 충분히 쌓이면 §6의 이론적 트레이드오프를 실측치로 검증할 수 있다.

9. 향후 개선 제안

  1. v2 ablation: 타깃 시장중립화만 적용한 버전과 aux 피처만 적용한 버전을 각각 따로 학습해, 두 변경의 기여도를 분리
  2. 여러 시드 반복학습: 최소 3~5개 시드로 각 버전을 재학습해, §6에서 관찰한 버전 간 순위 차이가 통계적으로 유의한지 확인
  3. REPORT.md 재생성 자동화: 재학습할 때마다 문서 텍스트도 최신 수치로 함께 갱신되도록 train.py 파이프라인에 통합(§7의 문서-실체 불일치 재발 방지)
  4. 거래비용 반영 백테스트: 수수료·세금·슬리피지를 반영한 순수익 기준으로 §5 표를 재작성
  5. 유동성/시가총액 필터의 학습 단계 반영 검토: 현재는 라이브 단계(체결 가능성)에만 있는 필터를 학습 유니버스 자체에도 적용할지 검토(초소형주 편중 완화)
  6. 라이브 트랙레코드 누적 후 모델 확정: 최소 수십~수백 거래일 실현수익률이 쌓이면, 이 문서의 백테스트 기반 트레이드오프(§6)를 실측치로 재검증해 최종 운용 모델을 좁힐지 결정
